# Phase 1 마무리 계획

기준: `0012974`. 요청 구문·Host·프레이밍·본문/청크 파서, 바이너리 echo,
고정 index 응답과 공통 HEAD/오류 송신은 이미 연결되어 있다. 완료 판정까지
다음 네 작업 단위가 남았다. P1-27/T-27은 Phase 2 시작으로 이관된 상태를 유지한다.
초기 명세 대조는 완료 9개, 부분 구현·검증 17개, 미착수 5개, 이관 1개다.
항목 크기가 달라 이 개수를 공수 진행률로 환산하지 않는다.

1. **실행 계약(P1-03/04)**: `app.c`에서 포트와 루트 디렉터리를 한 번 검증하고
   열린 루트 FD를 `webserver.c`에 넘긴다. 실제 listener, 누락/중복/잘못된 인자,
   루트 독립성 및 포트 충돌을 검증한 뒤 커밋한다.
2. **공개 정적 파일(P1-16~22)**: 라우터는 한 번 디코딩한 URL 경로를 분류하고
   앱은 루트 FD에 묶인 파일 해석기로 실제 공개 가능 여부를 결정한다.
   인덱스·리다이렉트·HEAD·MIME·내부 링크·접근 거부 및 스트리밍을 검증하고 커밋한다.
3. **연결 수명(P1-12/26/28)**: 단조 시계와 남은 시간으로 블로킹 I/O의 마감을
   강제한다. 응답 예산·정리와 JSONL 접근 로그를 연결한 뒤 시간 경계와 후속
   정상 요청, 로그의 상태·바이트·필드를 검증하고 커밋한다.
4. **완료 증빙(P1-29~32)**: 비특권 격리 Linux Docker에서 단위·실제 HTTP
   클라이언트·메모리·FD와 성능 기준선을 검증한다. 지원하지 않거나 실행하지
   못한 케이스는 PASS로 기록하지 않는다. 결과와 진행 원장을 별도 커밋한다.

## 정적 파일 세부 결정 (D-01/D-02/D-04)

다음은 구현자 결정이며 HTTP 표준이 강제하는 공개 정책이 아니다.

| 경우 | 결정 |
| --- | --- |
| 경로 해석 | 쿼리는 파일 선택에 쓰지 않는다. 경로는 한 번 디코딩한다. 인코딩된 `/`와 역슬래시, 잘못된 UTF-8은 400. 중복 `/`와 명시적 `.`·`..`는 403이며 정상 경로로 정규화하지 않는다. |
| 존재 공개 | 숨김 구성요소(요청과 링크 대상)·없는 파일·없어진 링크·인덱스가 없는 디렉터리는 404. 경계 이탈·권한 거부·특수 파일·순환 링크는 403. |
| 공개 범위 | `.html`, `.css`, `.js`, `.png`, `.jpg`, `.jpeg`만 ASCII 대소문자 구분 없이 허용한다. 요청 파일명과 최종 파일명이 둘 다 허용 목록에 있어야 한다. 인덱스 이름은 `index.html`이다. MIME은 실제 대상 확장자에 따른다. |
| 디렉터리 | 제공 가능한 인덱스를 확인한 후에만 끝 `/`가 없으면 308. 검증한 origin 경로에 `/`를 붙인 `Location`이며 Host와 쿼리는 복사하지 않는다. |
| 응답 순서 | 구문·프레이밍·Expect → 미구현 메서드 501 → 자원 판정 → 해당 자원의 허용 메서드 405/Allow → 필요한 본문 → 최종 응답. 디렉터리 308은 헤더만으로 확정한다. GET/HEAD 200은 공통 바디 프레이밍으로 본문을 받고 버린다. |

루트는 실행 시 디렉터리 FD로 고정한다. 루트 경로 자체는 운영자가 신뢰해
지정하며, 그 아래 일반 파일과 링크는 공개 정책에 따라 매 요청 다시 판정한다.
지원 대상은 Linux `openat2`(커널 5.6 이상, 컨테이너 정책에서 허용) 및
정상적인 `/proc/self/fd`가 있는 컨테이너다. 검증 프로파일은 대소문자 구분
overlayfs이며, 대소문자를 접거나 별칭을 생성하는 Windows 공유와 네트워크
파일 시스템을 정적 루트로 사용하는 구성은 검증 대상이 아니다.
루트 밖·하위 마운트·proc magic link는 허용하지 않으며 호환성 fallback은 없다.
루트 내부 상대·절대 링크는 검토한 구성요소를 매번 고정 루트 기준으로 다시
열 수 있을 때만 허용한다. 이전에 얻은 중간 디렉터리 FD로 남은 부분을 열지
않는다. 절대 링크는 루트의 실제 컨테이너 경로에 자기 완결적으로
포함되어야 하며, 루트의 파일 시스템 이름을 실행 중에 바꾸는 배치는 지원하지 않는다.
파일을 읽을 때는 종류를 확인한 동일 객체를 사용한다. 이 계약은 운영자가
직접 공개 루트에 놓은 일반 파일/하드 링크의 내용은 신뢰한다.
전송 중 증가분은 보내지 않고, 조기 EOF는 미완료 로그와 연결 닫기로 처리한다.
결정 자체는 실행 증빙을 대신하지 않는다.

## 컨테이너 검증 프로파일 (D-08)

Linux/amd64 개발 이미지에서 UID/GID 1000:1000, `--network none`, CPU 2개,
메모리 512 MiB, PID 128개, 열린 FD 256개 상한으로 실행한다. 클라이언트와
서버는 같은 컨테이너의 루프백만 사용한다. Windows/WSL bind mount의 POSIX
특성을 가정하지 않는다. 검증할 소스는 tar로 전달해 컨테이너 overlayfs에
풀고 테스트 파일과 정적 루트도 컨테이너 안에서 생성한다.

빌드와 검증은 서로 다른 컨테이너 실행에서도 같은 이미지 ID와 옵션을
기록한다. 일반·검사·성능 빌드를 분리한다. 수신/송신 마감의 통합 검사는
실제 블로킹 소켓을 사용하되 별도 테스트 바이너리에서만 시간을 단축한다.
운영 바이너리의 시간 설정은 CLI나 환경 변수로 바꾸지 않는다.
성능은 단일 활성 요청과 새 연결, warm cache, 고정 페이로드, 반복별
p50/p95/p99·처리량·실패·메모리·FD를 사용하며 임의 성능 합격선을 두지 않는다.

## 실행·연결 계약 (D-05/D-06/D-07)

- `--port`와 `--root`는 각 한 번 필수다. 포트는 1–65535의 십진수이며
  `127.0.0.1`에만 바인드한다. 운영 기본값·자동 포트·호스트 포트 공개는 없다.
  통합 테스트는 빈 포트를 예약한 뒤 넘기고, 바인드 완료 신호에 동기화한다.
- 헤더 10초/전체 수신 60초는 accept의 단조 시각 기준이다. 본문 무진행
  30초는 본문 단계 진입부터 실제 `recv` 진행(프레이밍 메타데이터 포함)마다 갱신한다.
  수신과 만료가 같은 시각이면 만료가 우선한다. 100 송신은 수신 마감을
  연장하지 않으며 본문 단계의 현재 마감보다 오래 기다리지 않는다.
- 최종 응답(408 포함)은 송신 시작 시 독립된 30초 예산을 한 번만 얻는다.
  이미 보낸 최종 응답을 대체하거나 재시도하지 않는다. 닫기와 남은 입력
  폐기는 다음 요청을 처리하지 않으며 별도 무한 대기를 두지 않는다.
- 접근 로그는 연결당 단일 JSONL 레코드다. `method`, `path`는 확정되지
  않았으면 `null`이며 path는 query/authority 없는 URL 경로다.
  `status`는 선택한 최종 응답 상태(없으면 `null`), `duration_ms`는 단조
  시계 기준 정수, `bytes_sent`는 100을 뺀 최종 응답의 커널 인수 바이트 수
  (헤더 포함), `complete`는 최종 응답을 모두 넘겼는지를 나타낸다.
  클라이언트의 수신 확인을 뜻하지는 않는다. 본문·인증정보·실제 파일 경로를
  기록하지 않는다.
