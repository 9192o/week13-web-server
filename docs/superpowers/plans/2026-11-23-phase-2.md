# Phase 2 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement and review one independently verified commit at a time.

**Goal:** Implement the agreed graceful shutdown, LT `epoll` concurrency, and HTTP/1.1 connection reuse on Linux Docker.

**Architecture:** First make shutdown independently observable on the sequential server. Next keep per-client HTTP progress outside the scheduler's call stack so an LT loop can resume bounded socket reads/writes. Finally reuse that state across requests on the same connection and compare the three agreed server/connection conditions.

**Tech Stack:** C17, Linux sockets, LT `epoll`, Python standard-library socket tests, GCC, Docker.

**Spec:** [Phase 2 requirements](../../PHASE_2_REQUIREMENTS.md)

## Global constraints

- Keep the Phase 1 HTTP parsing, framing, static-file boundary, echo, and timeout contracts unless the Phase 2 spec explicitly changes them.
- The server remains single-process and single-threaded; ET exists only in a standalone exercise.
- No runtime dependencies beyond C and platform APIs. Keep unrelated preview changes outside this worktree.
- The local base for the sequential comparison is `5b20a75`. Use matching optimization flags and a single container for the comparison.

## Review focus

- Signal before complete headers vs after semantic and framing validation: distinct shutdown outcomes.
- Buffered next-request bytes after both fixed-length and chunked body boundaries survive response writes.
- Partial writes, client half-close/reset, and stale readiness do not stall other clients or retain resources.
- An idle connection cannot delay shutdown, and a free slot cannot re-enable accepts during shutdown.
- Connection/timeout transitions must not accidentally carry request-local parser pointers, log counters, or response ownership into the next request.

## Work units

1. **Spec and plan:** add the agreed spec, plan and progress-ledger pointer; verify IDs and links.
2. **Graceful shutdown:** integrate the SIGINT/SIGTERM wakeup into accept and current-request waits in the sequential server; test idle/header/body/response cases before switching the scheduler. Keep the signal mechanism usable from the upcoming LT loop.
3. **LT event loop:** change the server from transaction-at-once to per-client header, body, continue, final response and bounded teardown progress. Preserve close-after-response during this unit. Add `--max-connections`, default 256, and disable listener interest when full. Verify parallel slow/fast clients, saturation/resumption, and shutdown. Retain timeout and partial-write checks.
4. **HTTP persistence:** honor a client's `Connection: close`; otherwise reuse fully consumed requests. Preserve pipelined bytes, apply 5-second idle and 100-request limits, and emit access records per request. Cover fixed and chunked bodies, safe/error close behavior, and request-to-request reset.
5. **LT/ET exercise:** use independent socket pairs and the same partial read; verify LT notification and no renewed ET notification without input. Keep out of production runtime.
6. **Benchmark:** compare A/B/C separately for static GET and POST echo at multiple concurrency levels. Verify bytes, count failures and actual reuse, record environment and repeats.
7. **Final evidence:** run Docker regression and socket suites, sanitizer/resource recovery, exercise, and benchmarks; update the ledger and document reported limitations. Do not calculate an improvement from mismatched environments or declare Phase 1's historical gaps closed by implication.
