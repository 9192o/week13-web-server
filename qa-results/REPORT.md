- **E02 백엔드 전달**: 세 후보 모두 본문이 덜 온 POST를 백엔드에 전달하지 않았다(백엔드 로그에 해당 요청 없음).
- **E03 413**: 세 후보 모두 `+1` 본문은 **선언 단계 거부**다. Content-Length만 보고 413을 보냈고 실제 본문은 처리하지 않았다.
- **E06 `/a/truncated`**: 세 후보 모두 백엔드 헤더(`Content-Length: 19`)를 그대로 전달하고, 2바이트 뒤 연결을 닫는다. 불완전한 본문을 완전한 성공으로 꾸미지 않는다.
- **공통 통과**:
  - E04: 8 MiB를 천천히 읽어도 해시가 일치하고, 중간에 끊은 뒤에도 새 GET이 정상이다.
  - E05: 두 번째 프로세스는 exit 1. INT·TERM 모두 진행 중 응답을 끝까지 보내고 exit 0. 신규 연결은 거부되고, 재기동 후 GET은 정상이다.
  - E07: 경로 탈출 7종에서 바깥 파일 바이트가 노출되지 않았다.
  - F05: 미완성 헤드 연결을 열어 둔 상태에서도 16연결이 모두 정상이다.

### M01 — Valgrind
- **ldc**: 직접·프록시 서버 모두 종료 시 `possibly lost: 288 bytes in 1 blocks`가 남아 exit 77이다.
  - 할당 위치: `pthread_create` ← `start_shutdown_watchdog (server_ev.c:276)` ← `server_ev_run (server_ev.c:1178)`.
  - 종료 감시 스레드를 join이나 detach하지 않고 끝나서 남은 TLS다. definitely·indirectly lost는 0이다.
- **eun 단위 테스트**: 실행 파일별 종료 코드는 모두 0이다. 다만 `test_server`가 fork한 **테스트 자식**에서 `definitely lost 1,048,576 B`가 나왔다.
  - 위치: `test_send_all_deadline_is_total`, `test_server.c:279`.
  - 원인: fork 전에 할당한 버퍼를 자식이 해제하지 않고 `_exit`한다. 서버 코드가 아니라 테스트 코드 문제다.
- **추적 범위**: CGI 자식은 추적하지 않았다(가이드 설정 그대로).

### M02 — FD·자식 프로세스
세 후보 모두 직접 서버·프록시에서 FD 수가 예열 직후와 3회 묶음 뒤에 같았다. 자식 프로세스는 0개였고, 종료 뒤 남은 프로세스도 없다.
